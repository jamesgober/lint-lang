# lint-lang v0.2.0 — The Lint Framework

**The core, and the hard part of the roadmap.** v0.2.0 turns the scaffold into a
working lint framework: rules written once against a small trait, configured per
rule with `allow` / `warn` / `deny`, and run together over a syntax tree in a single
walk. Every finding is a `diag-lang` diagnostic, so a lint warning renders with
source context exactly like a parse or type error. The surface is deliberately
small: one trait, four types, and one error.

## What is lint-lang?

The machinery for a compiler's lints — the checks for code that is legal but
probably wrong, needlessly complex, or against a project's style. Each check is a
separate rule a user can escalate to an error, leave as a warning, or switch off.
lint-lang owns no rules and no grammar: a language supplies both, and lint-lang
runs the rules, applies the user's configuration, and collects the results. Trees
come from `ast-lang`; findings are `diag-lang` diagnostics. It is the FEAT-tier lint
crate of the `-lang` language-construction family.

## What's new in 0.2.0

### `Rule` — one check

A rule has a stable `name` (what users configure it by), a `default_level`, and a
`check` called once per node. `check` takes `&self`: a rule's fields hold
configuration, and everything it needs about the node's position comes from the
context. The trait requires `Send + Sync`.

```rust
use lint_lang::{Context, Label, Rule};
# use lint_lang::{Id, Node, Span};
# enum Expr { Int(i64, Span), Neg(Id<Expr>, Span) }
# impl Node for Expr {
#     fn span(&self) -> Span { match self { Expr::Int(_, s) | Expr::Neg(_, s) => *s } }
#     fn each_child(&self, f: &mut dyn FnMut(Id<Self>)) { if let Expr::Neg(a, _) = self { f(*a) } }
#     fn map_children(&self, f: &mut dyn FnMut(Id<Self>) -> Id<Self>) -> Self {
#         match self { Expr::Int(v, s) => Expr::Int(*v, *s), Expr::Neg(a, s) => Expr::Neg(f(*a), *s) }
#     }
# }

struct DoubleNegation;
impl Rule<Expr> for DoubleNegation {
    fn name(&self) -> &'static str { "double-negation" }
    fn check(&self, node: &Expr, cx: &mut Context<'_, Expr>) {
        if let Expr::Neg(inner, span) = node {
            if let Some(Expr::Neg(..)) = cx.arena().get(*inner) {
                cx.report("negation of a negation", Label::new(*span, "these cancel out"));
            }
        }
    }
}
```

### `Linter` — configuration and one walk

`register` adds rules, `set_level` applies user configuration, and `run` lints a
tree. A run is a single iterative depth-first walk however many rules are
registered, so cost grows with tree size, not tree size times rule count. Rules at
`Allow` are never called, and when nothing is enabled the walk is skipped
entirely. `run_into` appends to a caller's buffer for batch linting, and a
configured linter is `Send + Sync`, so one instance serves every thread.

### `Level` — `allow`, `warn`, `deny`

The `rustc`/Clippy model. `Warn` findings carry `Severity::Warning`, `Deny`
findings `Severity::Error`. Levels parse from text, ignoring ASCII case, so
configuration files and command-line flags reduce to a loop over `set_level`. With
the `serde` feature they deserialize from the same lowercase strings.

### `Context` — position without state

At each node a rule sees the arena, the node's handle, its parent, its ancestors
(root first) and its depth — maintained by the walk at no extra cost. `report`
records a finding at the rule's configured severity; `emit` records a hand-built
diagnostic with secondary labels, notes, or help.

### `Finding` and `LintError`

A `Finding` is the rule's name plus its diagnostic, with `is_error` for deciding
whether a build fails and a one-line `Display` (`warning[rule]: message`). Findings
come back in a fixed order: depth-first pre-order by node, then rule registration
order. `LintError` covers the three configuration mistakes — duplicate rule,
unknown rule, invalid level — at setup time, leaving the linter unchanged. Running
a configured linter never fails.

### Examples, benchmarks, and tests

Three runnable examples (`quickstart`, `configure`, `parallel`) share a miniature
arithmetic language with a span-tracking parser and four realistic rules: one
correctness rule denied by default, one warning, one opt-in, and one configurable
nesting limit. Criterion benchmarks measure the traversal floor, the framework's
own overhead, per-rule scaling, and the all-allowed early exit. Property tests
check the runner against an independent model over random trees and random
configurations.

### Dependency wiring

`ast-lang` (the tree and the walk) and `diag-lang` (the finding format) are wired.
Both resolve to one `span-lang`, so a node's `Span` labels a diagnostic with no
conversion, and the types are re-exported. `pass-lang` is deliberately not wired: a
lint run is one fused walk, and a pass manager would turn it into one traversal per
rule. The reasoning is recorded in `dev/ROADMAP.md`.

## Verification

Run on Linux (WSL2 Ubuntu) with Rust stable and the 1.85 MSRV, and on Windows
x86_64 with stable. The same commands run in the configured CI matrix:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --no-default-features --lib -- -D warnings
cargo test
cargo test --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo build --no-default-features
cargo +1.85 test --all-features
cargo deny check
cargo audit
```

All green. Counts at this tag:

- Default features: 36 unit + 12 integration + 4 property + 63 doctests. The
  doctests include every `rust` example in `README.md` and `docs/API.md`, so the
  published examples cannot drift from the API.
- `--all-features`: adds 4 `serde` tests covering `Level`'s representation and a
  configuration map.

Benchmark baselines (WSL2, x86_64, release profile): a bare `ast_lang::walk` is
~1.9 ns per node; with one enabled no-op rule a run is ~4.7 ns per node; each
further enabled rule adds ~1 ns per node; the four example rules over a 135k-node
tree take ~1.5 ms including building their findings; and a linter with every rule
allowed returns in ~1.4 ns regardless of tree size.

## What's next

- **1.0.0 — API freeze.** Freeze the 0.2.0 surface as the 1.0 contract, mark
