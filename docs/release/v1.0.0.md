# lint-lang v1.0.0 — API Freeze

**The surface is stable.** v1.0.0 freezes the lint framework introduced in 0.2.0 as
the `1.x` contract: no breaking changes ship before `2.0`. There are no code
changes from 0.2.0. This release records exactly what is promised, including the
run semantics callers depend on, and completes the roadmap.

## What is lint-lang?

The machinery for a compiler's lints: named, configurable rules that run over an
`ast-lang` syntax tree in a single walk and report findings as `diag-lang`
diagnostics. A language supplies the rules and the grammar; lint-lang runs the
rules, applies the user's `allow` / `warn` / `deny` configuration, and collects the
results. It is the FEAT-tier lint crate of the `-lang` language-construction
family.

## What's frozen

The whole public surface — one trait, four types, one error, and the re-exports:

| Item | Contract |
|---|---|
| `Rule<N>` | `Send + Sync`; `name`, `check(&self, &N, &mut Context<'_, N>)`; provided `default_level` (`Warn`). |
| `Linter<N>` | `new`, `register`, `set_level`, `level`, `rules`, `len`, `is_empty`, `run`, `run_into`; `Send + Sync`. |
| `Context<'a, N>` | `arena`, `id`, `parent`, `ancestors`, `depth`, `rule`, `severity`, `report`, `emit`. |
| `Level` | Exhaustive `Allow` / `Warn` / `Deny`; `severity`, `as_str`, `Display`, `FromStr`. |
| `Finding` | `rule`, `diagnostic`, `severity`, `is_error`, `into_diagnostic`, `Display`. |
| `LintError` | `#[non_exhaustive]`: `DuplicateRule`, `UnknownRule`, `InvalidLevel`. |
| Re-exports | `Arena`, `Id`, `Node`, `Span` (`ast-lang` 1.x); `Diagnostic`, `Label`, `Severity` (`diag-lang` 1.x). |

### Behaviour that is part of the contract

- Findings come back in depth-first pre-order by node, then rule registration
  order.
- A rule at `Allow` is never called; a linter with nothing enabled does not walk.
- `Warn` maps to `Severity::Warning` and `Deny` to `Severity::Error` for findings
  recorded with `Context::report`.
- A rejected `register` or `set_level` leaves the linter unchanged.
- A root handle that names no node produces no findings.
- `Level` reads and writes as `allow` / `warn` / `deny`, both as text and through
  `serde`. `Finding` displays as `severity[rule]: message`.

### Two deliberate choices

- **`Level` is exhaustive.** The three levels are a closed set, so downstream code
  can `match` on them without a wildcard arm. A future level would be a `2.0`
  change.
- **`Rule` requires `Send + Sync`.** That is what makes a configured `Linter`
  shareable across threads, and it stays.

### What can still grow in 1.x

New defaulted methods on `Rule` (for example a description for `--explain`), new
methods on the other types, and new `LintError` variants — all additive. The
candidates on the roadmap are a "warnings as errors" switch, per-rule
descriptions, and rule groups.

The full statement lives in [`docs/API.md#stability`](https://github.com/jamesgober/lint-lang/blob/main/docs/API.md#stability).

## Breaking changes

**None.** The API is identical to 0.2.0. Upgrading is a version bump:

```toml
[dependencies]
lint-lang = "1"
```

## Verification

Run on Linux (WSL2 Ubuntu) with Rust stable and the 1.85 MSRV, and on Windows
x86_64 with stable; macOS runs through the configured CI matrix:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --no-default-features --lib -- -D warnings
cargo test --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo build --no-default-features
cargo +1.85 test --all-features
cargo run --example quickstart && cargo run --example configure && cargo run --example parallel
cargo deny check
cargo audit
cargo publish --dry-run
cargo bench --bench bench
```

All green. Counts at this tag: 36 unit + 12 integration + 4 property + 4 `serde` +
63 doctests (every `rust` example in `README.md` and `docs/API.md`).

Benchmarks (WSL2, x86_64, release profile) match 0.2.0 within run-to-run noise: a
bare walk ~1.9–2.0 ns per node, one enabled rule ~4.7 ns per node, each further
enabled rule ~1.0–1.2 ns per node, the four example rules over a 135k-node tree
~1.5 ms, and an all-allowed linter ~1.3 ns regardless of tree size.
